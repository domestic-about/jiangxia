# 环境病灶：macOS 系统代理让 JVM 把发往 127.0.0.1:9000(MinIO) 的请求丢给代理
# 复现时间 2026-09-22；与 ticket 代码无关 —— 挂的是框架自带的 POST /resource/oss/upload。

$ scutil --proxy   # 本机的系统代理
  HTTPEnable : 1
  HTTPPort : 1081
  HTTPProxy : 127.0.0.1
  HTTPSEnable : 1
  HTTPSPort : 1081
  HTTPSProxy : 127.0.0.1

$ java -XshowSettings:properties -version 2>&1 | grep -E 'proxyHost|nonProxyHosts'
    http.nonProxyHosts = captive.apple.com|*.captive.apple.com|localhost|*.localhost|192.168.3.1.dns|*.192.168.3.1.dns|local|*.local|172.16.0.0/12|*.172.16.0.0/12|10.0.0.0/8|*.10.0.0.0/8|198.18.0.0/15|*.198.18.0.0/15|192.168.0.0/16|*.192.168.0.0/16
    http.proxyHost = 127.0.0.1
    http.proxyPort = 1081
  ↑ JDK 从 macOS 系统设置灌进 http.proxyHost；而 http.nonProxyHosts 里**没有 127.0.0.1**（只有 localhost）
  ↑ curl 不受影响：它认环境变量 NO_PROXY=127.0.0.1

$ 修法（本票采用）：把 127.0.0.1 加进 JVM 的 nonProxyHosts —— 写进 code/deploy/dev/.env（**git 忽略的**本机环境文件）
   JAVA_TOOL_OPTIONS='-Dhttp.nonProxyHosts=localhost|127.0.0.1|*.local|local'
   qa-up.sh 起后端前会 'set -a; . code/deploy/dev/.env; set +a'，所以任何一次 qa-up 都会带上它。
   修后：POST /resource/oss/upload -> 200（accept 1 全程绿）
   ★ 值必须带引号：| 在 shell 里是管道，不引起来会 . .env 时把后半截当命令跑（本票踩过一次）。
