# ADR-0010: 数据模型主干——一个样本主档，工序记录都挂在它下面

**决策者**: 待 Kevin 过目（数据模型主干属于不可逆的一类；售前技术判断 §3.1 已给 Kevin 看过同一思路，但没有明确点头）
**关联**: REQ-SAMPLE-005 / 008 / 012、REQ-CRYO-004、REQ-QC-001 / 005 / 007、field-ssot.yaml 全部业务表

## 背景

甲方给的是 7 份互相独立的模板，但说的话是「内部编号贯穿到底」「外部填的实时同步到该表」「所有样本一张表」「外部看得到自己样本的包埋、培养情况」。
这四句话只有在「一个样本是一个实体、别的记录都挂在它下面」时才同时成立。

## 决策

按 frontmatter。

- 「照 7 份模板建 7 张互不关联的表」不采纳：那样「实时同步」「外部看包埋情况」「切片染色提示」全得靠跨表对名字去凑。
- 「各工序表用内部编号字符串互相关联」不采纳：外部刚提交、还没核验的样本没有内部编号；内部编号填错要改时，字符串关联会断一片。
- 「冻存剩余支数允许直接改数字」不采纳：甲方要的是「取走需要追溯」，能直接改数字就等于没有追溯。盘点对不上走「盘点调整」流水并写原因。

## 后果

- 四张 Excel 是**按模板列序导出的视图**，不是四张物理表的直接转储。
- 三份质控文档「每个样本各一份」是默认口径：若甲方日后要同一个样本出多份类器官质控表（比如按代数），改动是去掉一个唯一索引 + 列表页，模型不用推翻。
- 外部样本核验为「有效」时才要求填内部编号；内部编号唯一性用部分唯一索引（只约束非空且未删除的行）。
- 2026-09-17 甲方看设计稿后要求「提交后可以修改」（CR-20260917-04）：出入库登记填错了可以改、可以删（软删），初始支数也可以改。
  剩余仍然不存数字、不给直接改的入口，由初始支数与未删登记算出；每次改删都锁批次行后按时间逐笔重算，任何一步为负就拒绝。
  所以上面那条「不采纳」照旧成立：能改的是「当时登记的是什么」，不是「现在还剩几支」。
- 2026-09-17 晚外部也能提交石蜡包埋送样（CR-20260917-05）：石蜡包埋记录上加了提交来源、提交人与核验三态（同样本主档那一套），
  石蜡块编号改为核验有效时才必填。记录照旧用 sample_id 挂在样本下，外部只能挂本人送检过的样本。
