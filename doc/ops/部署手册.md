### 1.2 机器规格与数据盘

* 2 核 4G（本手册 §2 的容量账就是按它算的）；系统盘 ≥ 40G，**另挂一块数据盘**给数据。
* 数据盘挂到 `${LQG_DATA_DIR}`（默认 `/opt/lqg`）。**为什么必须是独立盘**：
  * PostgreSQL 的数据（`pgdata`，bind mount）、备份 dump 的落地、日志、`tmp` 都在这里；
  * 全在一个盘上时，一次 `pg_dump` + 一次大文档渲染就能把系统盘写满 → 容器全挂。
* 挂盘（示例，设备名按实际改）：

```bash
lsblk                                   # 认准数据盘，别挂错
mkfs.ext4 /dev/vdb
mkdir -p /opt/lqg
echo '/dev/vdb /opt/lqg ext4 defaults,noatime 0 2' >> /etc/fstab
mount -a && df -h /opt/lqg
```

> ★ `deploy.sh` 的 preflight 不检查挂载（本地跑，看不到远端），但 `remote/00-host.sh`
> 会 `df -h ${LQG_DATA_DIR}` 并把结果打出来 —— 看到 `/opt/lqg` 和 `/` 是**同一个设备**
> 就说明盘没挂上，先挂盘再起容器。

### 1.3 安全组（云控制台，不是机器上的防火墙）

入方向**只开**：`22/tcp`（SSH，建议限源 IP）、`80/tcp`、`443/tcp`。
出方向默认全开（要拉镜像、要签证书、要连 OSS）。

**5432 / 6379 / 3000 / 8080 一条都不许有。** 这是 accept 2 第 1 段的判据：
`nc -z <域名> 5432` 等四条必须连不通。容器层面也已经不映射（`docker-compose.yml` 里
只有 `nginx` 段有 `ports:`），但**安全组是第二道门 —— 两道都要关**。

### 1.4 机器上的系统层准备

`remote/00-host.sh` 做五件事：时区、swap、数据盘核对、docker 日志轮转、防火墙。
它要 sudo/root，所以是**手工跑一次**（`deploy.sh all` 不会替你跑）：

```bash
ssh <生产机> 'install -d /opt/lqg'
# 把 remote/ 同步上去（或直接 git clone 仓库到机器上）
ssh <生产机> 'cd /opt/lqg && bash remote/00-host.sh'
```

为什么需要那 2G swap：`gotenberg` 的 LibreOffice 转一个大文档会瞬间吃内存，
4G 机器上没有 swap 就是直接 OOM-kill（`backend` 有 `ExitOnOutOfMemoryError`，
它自杀重启是**设计好的**，见 §8）。

## §2 容量账（2 核 4G 怎么分）

| 服务 | 上限 | 依据 |
|---|---|---|
| postgres | `shared_buffers=1GB` + 连接与 work_mem ≈ 1.3G | `docker-compose.yml` 的 `command`；`max_connections=100` 对上后端 `maxPoolSize=20` |
| gotenberg | **1G**（`mem_limit: 1g` + `memswap_limit: 1g` + `cpus: 1.0`） | 票面 §2 硬要求；`mem_limit` 而不是 `deploy.resources.limits`（后者在普通 compose 下被静默忽略） |
| backend | **`-Xmx1g`**（`JAVA_TOOL_OPTIONS`） | 票面 §2 硬要求；覆盖镜像里给测试机的 `MaxRAMPercentage=60` |
| redis | 256MB + `allkeys-lru`，关快照 | 只放会话 / 锁 / 缓存（数据以 PG 为准，ADR-0002） |
| nginx | 可忽略 | 静态 + 反代 |
| 系统 + docker | 剩余 ≈ 0.4G + swap | 别在这台机器上跑别的东西 |

> ★ **为什么 `shm_size: 1gb`**：PostgreSQL 的并行查询走 POSIX 共享内存，
> 容器默认的 64MB `/dev/shm` 会让并行查询报
> `could not resize shared memory segment`。给到与 `shared_buffers` 同量级即可。
>
> ★ **为什么 gotenberg 的内存上限不用 `deploy.resources.limits.memory`**：
> 那个键只在 `docker compose --compatibility` 或 Swarm 模式下生效，普通 `docker compose up`
> 会**静默忽略** —— 现场表现是「文件里写了 1G，实际没限住」。

## §3 `.env` 每个键的含义（`code/deploy/prod/.env.example` 的逐行说明）

`.env` 是生产的**全部密钥**（服务器上也留一份 `${LQG_DATA_DIR}/.env`，600）。它不进 git
（根 `.gitignore` 的 `code/deploy/**/.env`；accept 2 第 5 段还会 `git ls-files` 复核）。

### 3.1 部署目标

| 键 | 含义 | 取值来源 | 本票状态 |
|---|---|---|---|
| `LQG_PROD_HOST` | 生产机公网 IP | 云控制台 | ⛔ 待 owner（B2） |
| `LQG_PROD_SSH` | SSH 目标，形如 `root@1.2.3.4` | 同上 | ⛔ 待 owner（B2） |
| `LQG_PROD_DOMAIN` | 已备案的生产域名（**必须是域名**：Let's Encrypt 不给裸 IP 签证书） | 域名服务商 + ICP | ⛔ 待 owner（B2） |
| `LQG_ICP_LICENSE` | 备案号（页脚展示用） | ICP 备案回执 | ⛔ 待 owner（B2） |
| `LQG_PROD_SSH_PORT` | SSH 端口，默认 22 | 机器配置 | — |
| `LQG_DATA_DIR` | 数据盘根目录，默认 `/opt/lqg` | §1.2 | — |
| `LQG_HTTP_PORT` / `LQG_HTTPS_PORT` | **给 deploy.sh 自检用**，不是 compose 的映射值。⚠️ 不要在这里加 DB/Redis/Gotenberg/backend 的端口 | 固定 80 / 443 | — |

### 3.2 口令类（deploy.sh 首次运行可现场生成）

| 键 | 含义 | 备注 |
|---|---|---|
| `LQG_DB_NAME` | 库名，固定 `lqg`（**不许含 `test`**） | `doc/verify/reseed.sh` 的护栏靠这个字符串挡住「误对生产灌 seed」 |
| `LQG_DB_USER` | 库用户，默认 `lqg` | |
| `LQG_DB_PASSWORD` | PG 口令 | 只进 `.env` 与 PG 容器 |
| `LQG_REDIS_PASSWORD` | Redis 口令 | ★ **必须设**：Redisson 配了口令就发 `AUTH`，服务端没口令时后端直接起不来 |
| `LQG_ENCRYPT_PASSWORD` | **字段加密口令**（ADR-0006：供体姓名 / 住院号 / 患者编号三列） | ★ **必须 ≠ `LqgTestAesKey#01`**（`preflight` 硬拦）。**丢了 = 这三列永远读不出来** → §9 交接 |

### 3.3 微信与 OSS

| 键 | 含义 | 取值来源 | 本票状态 |
|---|---|---|---|
| `LQG_WX_APPID` / `LQG_WX_SECRET` | 甲方小程序 appid / secret | 微信公众平台 | ⛔ 待甲方（SYS-RELEASE-001）；留空则线上小程序登录不可用，但后端照常起 |
| `LQG_OSS_BUCKET` / `LQG_OSS_ENDPOINT` / `LQG_OSS_REGION` | 私有桶与访问点 | 阿里云 OSS 控制台 | ⛔ 待 owner（B1） |
| `LQG_OSS_ACCESS_KEY_ID` / `_SECRET` | **只授这一个桶**的 RAM 子账号 AK | RAM 控制台 | ⛔ 待 owner（B1）。**不进仓库**（accept 2 第 6 段 `git grep 'LTAI…'`） |
| `LQG_OSS_PREFIX` | 业务对象前缀，默认 `lqg/` | 固定 | ★ 与备份前缀 `backup/` 分开，免得生命周期规则把业务文件一起过期 |
| `LQG_ALERT_WEBHOOK` | 飞书自定义机器人地址 | 飞书群设置 | ⛔ 待 owner；留空则 healthcheck 退化成打日志 |

### 3.4 构建与证书

| 键 | 含义 | 备注 |
|---|---|---|
| `LQG_BUILD_COMMIT` | 反 stale：注入 `/lqg/sys/ping` 的 `buildCommit` | `deploy.sh` 每次用 `git rev-parse --short=7 HEAD` 覆写；**回滚就是把它改回上一个提交号**（§6） |
| `LQG_CERT_EMAIL` | acme.sh 注册与到期提醒邮箱 | 必填（`deploy.sh cert` 会检查） |
| `LQG_CERT_CA` | `letsencrypt`（默认）/ `zerossl` / `buypass` | 国内机器连不上 LE 时换 |

## §4 首次上线：从空服务器到上线（每一步在做什么）

```bash
cd code/deploy/prod
cp .env.example .env && chmod 600 .env      # 填 §3 里 owner 已提供的值
bash deploy.sh preflight                    # ① 本地六道自检（不联网）
ssh <生产机> 'cd /opt/lqg && bash remote/00-host.sh'   # ② 系统层（§1.4）
bash deploy.sh all                          # ③ 下面全部串起来
```

### 4.1 `preflight`（本地，不联网）

六道自检，任何一道红都不许往下走：

1. `.env` 硬口径：域名/主机/库名不许是测试的；加密口令不许是占位或测试口令。
2. `docker compose config -q`：用真实 `.env` 展开，任何必填缺失（`${VAR:?}`）在这里红。
3. **端口纪律**：`ports:` 只允许出现在 `nginx` 段；且不许命中 `5432/6379/3000/8080` 的映射写法。
4. 仓库里没有 AK 形态字符串、没有 `.env` 被跟踪。
5. `application-prod.yml` 不含三个危险开关。
6. `remote/*.sh` 与 `healthcheck.sh` 过 `bash -n`。

### 4.2 `artifacts`（本地构建）

* **后端 jar**：`mvn -pl ruoyi-admin -am -DskipTests package`。
  ★ **本地不建镜像**（开发机是 arm64、生产机是 amd64，本地镜像上机是 `exec format error`）——
  只把**与架构无关的 jar** rsync 上机，在服务器原生构建。理由同测试环境：
  `code/deploy/common/README.md`。
* **工作台 dist**：`pnpm build:prod`（`code/plus-ui`，走 `.env.production`）。
  ★ **不能用 `build:test`**：那个 mode 把 `VITE_APP_ENCRYPT` 关成 `false`，
  而后端 prod 的 `api-decrypt.enabled` 是 `true`（`application.yml` 缺省）—— 两边不一致会让
  工作台登录**一律失败**。

### 4.3 `upload`（rsync）

上传：jar + gotenberg 构建上下文 + `docker-compose.yml` + `nginx/` + `remote/` +
`healthcheck.sh` + `oss-init.sql` + plus-ui dist + **`.env`（scp 后立刻 `chmod 600`）**。
最后在服务器上把 `nginx/workspace.conf` 里的 `__LQG_DOMAIN__` 渲染成真域名
（**不用 envsubst**：nginx 配置里满是 `$host` / `$scheme`，envsubst 会把它们一起吃掉）。

### 4.4 `up`（远端 `remote/01-up.sh`，长操作分离执行）

1. 目录与权限：建 `logs/ pgdata/ tmp/ certs/ acme-webroot/`；
   **`chown -R 70:70 pgdata`**（postgres 官方镜像以 uid 70 跑，bind mount 的 root 独占目录会让 `initdb` 直接失败）；`tmp` 给 1777（容器里非 root 也要写）。
2. 渲染 nginx 域名占位。
3. **证书不存在时先签一张自签占位**（3 天）：nginx 配置引用证书文件，没有文件时 `nginx -t` 会失败
   → 容器起不来 → 80 端口没人提供 → acme 的 webroot 挑战也没法做。占位证书只为「让 nginx 起得来」，
   紧接着 §4.5 就用真证书覆盖并 reload。
4. `docker compose build backend gotenberg`（服务器原生 amd64）。
5. `docker compose up -d`，然后**等健康最多 8 分钟**（backend 的 `start_period` 是 180s，
   首次 Flyway 迁移也要时间）。
6. 端口纪律复核：宿主上不许有 `5432/6379/3000/8080` 在监听。

### 4.5 `cert`（远端 `remote/03-cert.sh`）

acme.sh + **webroot** 校验：

* **为什么 webroot 而不是 standalone**：standalone 要停掉占着 80 的 nginx，等于每次续期都停站。
* **为什么不是 DNS 校验**：要域名服务商的 API 密钥，那是另一件 owner 待提供的事。
* webroot 目录 `${LQG_DATA_DIR}/acme-webroot` 被 compose 挂进 nginx 容器的 `/var/www/acme`，
  80 端口的 `location ^~ /.well-known/acme-challenge/` 从这里读。

**★ 续期后必须 reload nginx —— 这是最容易漏的一步。** nginx 只在启动 / reload 时读证书文件；
acme.sh 默认只把新证书换到自己的路径，不 reload 的话新证书要等到下次重启才生效
（症状：证书明明续了，浏览器还是旧的 / 告警在到期前一天响）。
所以本票把 reload 做成 acme.sh 的 `--reloadcmd`：

```
--reloadcmd "bash ${LQG_DATA_DIR}/remote/06-cert-install.sh <域名> <cert-origin>/privkey.pem <cert-origin>/fullchain.pem"
```

`06-cert-install.sh` 做的事：把证书从 `cert-origin/`（acme.sh 的落地目录，compose 不挂它）
**先写 `.tmp` 再 `mv`** 搬到 `certs/<域名>/`（避免 reload 撞上「证书写了一半」的窗口），
`chmod`，然后 `docker exec lqg-prod-nginx nginx -t && nginx -s reload`。
★ **`--reloadcmd` 在每次 `--issue` / `--install-cert` 时都要带**（acme.sh 把它记在
`/root/.acme.sh/<域名>_ecc/<域名>.conf` 的 `Le_ReloadCmd` 里）—— `remote/03-cert.sh` 就是这么做的。

验证：

```bash
openssl x509 -in /opt/lqg/certs/<域名>/fullchain.pem -noout -dates
openssl x509 -in /opt/lqg/certs/<域名>/fullchain.pem -noout -checkend 1296000   # > 15 天
echo | openssl s_client -servername <域名> -connect <域名>:443 2>/dev/null | openssl x509 -noout -dates
crontab -l | grep acme
```

### 4.6 `oss-init`（远端 `remote/04-oss-init.sh` + `oss-init.sql`）

**手工执行一次，不进 Flyway**：

* 这一行里带生产 AK/SK → 进 Flyway = 进仓库（accept 2 第 6 段必红）；
* Flyway 在 dev / test / prod 都会跑 → dev 有 MinIO、test 有自己的桶，不该被生产桶覆盖。

脚本做三件事：核对桶 ACL（`ossutil bucket-acl`，没授 `GetBucketAcl` 时只警告）→
在 **postgres 容器里** `psql -v` 执行 `oss-init.sql`（AK 从服务器 `.env` 取，
用 `:'ak'` 让 libpq 安全转义）→ 回读 `sys_oss_config`（**不打印 AK 原值**，只看 `SET(len=…)`）。

写入的那一行要点：`config_key='aliyun'`、`access_policy='0'`（**私有**）、
`status='0'`（**默认**）、`prefix='lqg/'`、`is_https='Y'`。
★ 两个「两道门」：(a) 后端签私有 URL（这一列），(b) **桶本身的 ACL 必须是私有** ——
桶若是公共读，裸地址依然匿名可读，accept 2 第 4 段会红（而且要当作真问题处理）。

### 4.7 `cron`

`remote/05-cron.sh` 生成 `${LQG_DATA_DIR}/healthcheck.env`（600，只含 healthcheck 需要的
四个值 —— 不把 AK 等无关密钥带进一个每 5 分钟就跑的脚本的环境），然后幂等装 crontab：

```
*/5 * * * * /opt/lqg/healthcheck.sh >> /opt/lqg/logs/healthcheck.log 2>&1 # LQG-PROD-001-healthcheck
```

装完**立刻跑一次**，确认脚本本身能跑（不是等 5 分钟才知道）。

### 4.8 `verify`（从本机打）

打六件事：工作台首页 200、http 跳 https、`/lqg/sys/ping` 匿名 401（接口不 `@SaIgnore`，
这也是 accept 1 第 3 段的口径）、证书剩余天数、`5432/6379/3000/8080` 公网不可达、
容器健康。**需要登录态的断言**（ping 的 `profile/encryptEnabled/mockLogin`、
mock 登录被拒、OSS 匿名 403）见 §12。

## §5 日常改配置与再次部署

```bash
# 只改配置（.env 里某个值）
vim .env && bash deploy.sh upload && bash deploy.sh up      # up 会重建镜像（秒级）并滚动重启

# 只改 nginx 配置
vim nginx/workspace.conf && bash deploy.sh upload
ssh <生产机> 'cd /opt/lqg && docker compose exec nginx nginx -t && docker compose exec nginx nginx -s reload'

# 只改代码
git checkout <目标提交> && bash deploy.sh all               # 或 artifacts + upload + up
```

★ 服务器上的 `${LQG_DATA_DIR}/.env` 是**运行用的那一份**；本地 `.env` 是投放源。
改口令要**两边都改**（`deploy.sh upload` 会把本地那份覆盖过去，所以以本地为准即可 ——
但如果你在服务器上直接改过而没同步回来，下次 `upload` 会把它冲掉）。

## §6 回滚到上一个镜像

**镜像 tag = 提交号**（`lqg-backend:<7 位 sha>`），所以回滚不需要重新构建：

```bash
# 1) 看服务器上有哪些镜像
ssh <生产机> 'docker images lqg-backend --format "{{.Tag}}\t{{.CreatedAt}}"'

# 2) 回滚（deploy.sh 会把 .env 的 LQG_BUILD_COMMIT 改成该提交号，再 up -d backend）
bash deploy.sh rollback <上一个提交号>

# 3) 确认 /lqg/sys/ping 的 buildCommit 回到了那个值
export LQG_VERIFY_ENV_FILE=doc/verify/verify.prod.env
bash doc/verify/api.sh --as admin GET /lqg/sys/ping | jq '.data.buildCommit'
```

★ **注意两件事**：

1. **数据库 schema 不回滚。** Flyway 是单向的：回滚代码不会撤掉已经跑过的迁移。
   如果新版本带了一个不兼容的迁移，回滚应用也救不回来 —— 上线前的迁移要按「向后兼容」写
   （加列 / 加表可以，删列 / 改类型不行）。
2. **回滚也要看 compose。** 如果那次部署同时改了 `docker-compose.yml`（例如加了挂载），
   `docker images` 里的旧镜像还在，但 compose 文件是新的。真正做到「回到上一个状态」要
   `git checkout <那个提交> -- code/deploy/prod/` 再 `upload + up`。

## §7 怎么走 SSH 隧道连数据库（生产 5432 不在公网）

生产的 postgres **不映射任何宿主端口**（accept 2 第 1 段就是要 `nc` 打不通）。
要连库有两条路：

### 7.1 隧道（本机图形客户端 / `psql` 都能用）

```bash
# 本机 15432 → 生产机上「容器内」的 5432
ssh -N -L 15432:127.0.0.1:5432 <生产机>        # ← 这样不行：宿主上并没有 5432 在监听
```

★ **坑**：postgres 在容器里，宿主上**没有** 5432 监听，所以 `-L 15432:127.0.0.1:5432` 连不上。
两种正确做法：

```bash
# (a) 让 SSH 直接穿进 compose 网络（推荐）：容器名在生产机上是可解析的
ssh -N -L 15432:lqg-prod-postgres:5432 <生产机>
#     ★ 需要生产机的 sshd 允许 GatewayPorts 之外的东西；容器名解析依赖 docker 的 DNS，
#       只在容器网络内可用。若不通，用 (b)。
# (b) 在生产机上先开一个宿主环回转发（临时，用完删）——不用改 compose：
ssh <生产机> 'docker run -d --rm --name lqg-ssh-tunnel --network lqg-prod_default \
   -p 127.0.0.1:15432:5432 alpine/socat tcp-listen:5432,fork,reuseaddr tcp-connect:lqg-prod-postgres:5432'
ssh -N -L 15432:127.0.0.1:15432 <生产机>       # 本机 15432 → 生产宿主环回 15432 → 容器 5432
# 用完：ssh <生产机> 'docker rm -f lqg-ssh-tunnel'
```

> ★ 无论哪条路，**只绑环回**（`127.0.0.1`）：`-p 15432:5432` 会把库暴露到公网，
> 那正是 accept 2 第 1 段要红的行为。

连上以后（本机）：

```bash
PGPASSWORD="$(ssh <生产机> 'sed -n "s/^LQG_DB_PASSWORD=//p" /opt/lqg/.env')" \
  psql -h 127.0.0.1 -p 15432 -U lqg -d lqg -c '\dt t_lqg_*'
```

### 7.2 直接在容器里敲（最省事，改数据之前推荐）

```bash
ssh <生产机> 'docker exec -it lqg-prod-postgres psql -U lqg -d lqg'
# 备份 / 导出走这一层：docker exec ... pg_dump（SYS-BACKUP-001 的 backup.sh 就是这么做的）
```

## §8 重新加载 / 重启 / 停机

| 想做的事 | 命令 | 影响 |
|---|---|---|
| reload nginx（改配置、换证书后） | `docker exec lqg-prod-nginx nginx -t && docker exec lqg-prod-nginx nginx -s reload` | 不断连接 |
| 重启后端 | `cd /opt/lqg && docker compose restart backend` | 短暂 502（几秒 ~ 1 分钟，看启动时间） |
| 重建后端（换镜像） | `docker compose up -d backend` | 同上，但会换成 `.env` 里 `LQG_BUILD_COMMIT` 指的那个 tag |
| 停全部（保留数据） | `bash deploy.sh down` | 站点不可用；**数据卷与 `/opt/lqg` 全部保留** |
| 看某容器日志 | `docker compose logs -f --tail=200 backend` | — |

★ **后端 OOM 会自杀重启**：`JAVA_TOOL_OPTIONS` 里有 `-XX:+ExitOnOutOfMemoryError`。
这是**设计好的**（`restart: unless-stopped` 会拉起来，不带病苟活）。
看到 `lqg-prod-backend` 有 `RestartCount` 增长 → 去 `docker inspect lqg-prod-backend --format '{{.RestartCount}}'`
与 `docker compose logs backend | grep -i 'OutOfMemory\|Killed'` 查，别只是重启了事。

## §9 首个管理员：授权 + 停用上游默认账号（上线当天必须做）

上线后的顺序（**不能跳**）：

1. **用超管登录**工作台：`https://<域名>/`。
   上游 baseline 带了一个默认超管账号 `admin`，初始口令在若依的上游文档里是公开的 ——
   **这一条正是要处理的风险**。
2. **在「内部人员授权」里按甲方管理员的手机号授权**（AUTH-STAFF-001）。
   甲方管理员手机号是 owner 待提供项（B4，见 `doc/handover/d8-blockers.json`）；
   没拿到之前，工作台只有 `admin` 一个可用账号。
3. **停用上游默认 `admin`**：
   * 把 `admin` 的口令改成**随机强口令**（≥ 20 位随机）；
   * 或者直接停用该账号（若 `admin` 是你唯一入口，先建好甲方管理员账号再停）；
   * **把这个随机口令记进交接单**（而不是留在聊天记录里）。
4. **交接单上要记的三样**（缺一样都不算交接完成）：
   * 随机化后的 `admin` 口令（或「已停用」+ 停用时间）；
   * 甲方管理员账号（手机号 / 角色）；
   * **`LQG_ENCRYPT_PASSWORD`（字段加密口令）**：
     ```
     ssh <生产机> 'sed -n "s/^LQG_ENCRYPT_PASSWORD=//p" /opt/lqg/.env'
     ```
     ⚠️ **丢了这三列就永远读不出来**（AES 无后门）：另存一份给 Kevin，**不要**写进仓库、
     不要写进工单系统、不要只存在部署那台机器上。

★ 不要 mock：生产**拒绝** mock 登录（ADR-0008，`MockLoginGuard` 在启动时把关），
所以上面每一步都必须用真实手机号 / 真实口令（B4）。

## §10 数据初始化：生产**不灌 seed**

* 生产库由**基线迁移 + 业务迁移**建起来（Flyway 在 backend 首次启动时跑），
  里面没有测试样本、没有 `lqgadmin/admin123`。
* `doc/verify/reseed.sh` 会 `TRUNCATE` 并灌 `doc/verify/seed/`；
  它的护栏是「库名不含 dev/test 就拒绝执行」。生产库名固定 `lqg`，
  所以在生产上跑它会**被拒绝**——这是设计，不是故障。
* 系统参数（`lqg.cryo.overdue-days` / `lqg.ext.show-internal-no` 等）如果 baseline 没带，
  上线后在工作台「系统管理 → 参数设置」里按甲方口径设一次（CR-20260918-07）。
* 生产 OSS 配置走 §4.6 的 `oss-init.sql`（**不是** seed）。

## §11 生产验收怎么跑（acc1 / acc2）

`doc/verify/verify.prod.env.example` 里逐键写了**去哪取**，并给了分段手工跑的命令。

2. **acc2 的 OSS 段**里那句 `api.sh` 只是「预热」，stdout 被丢弃；逐段手工跑时跳过它。

## §13 出问题先看哪

| 症状 | 先看 | 常见原因 |
|---|---|---|
| 站点 502 / 打不开 | `docker compose ps` → `docker compose logs --tail=100 nginx backend` | backend 还在启动（`start_period` 180s）、后端连不上库 / Redis 口令不一致 |
| 后端起不来 | `docker compose logs backend \| tail -50` | `LQG_DB_PASSWORD` 缺、Redis 口令不一致（`ERR AUTH`）、`mybatis-encryptor.password` 未配置 |
| 证书告警但文件是新的 | 线上指纹 vs 磁盘指纹 | **续期没 reload**（§4.5） |
| 上传 413 | nginx 的 `client_max_body_size` | 提到 60m 之外的需求要同时改后端 multipart 上限 |
| 工作台登录失败、后端没报错 | `code/plus-ui/.env.production` 的 `VITE_APP_ENCRYPT` | 前端加密开着而后端 `api-decrypt` 关着（或反过来）—— 两边必须同口径 |
| `/lqg/sys/ping` 里 `profile` 是 `test` | `docker-compose.yml` 的 `SPRING_PROFILES_ACTIVE` 与 `command` | 用了测试机的 compose / 镜像 |
| 磁盘告警 | `du -sh /opt/lqg/*` | 备份 dump 堆积（SYS-BACKUP-001 的 30 天规则）、docker 日志、`tmp/` 里的渲染中间产物 |

更多日常操作见 `doc/ops/运维手册.md`。
