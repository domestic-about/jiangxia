## §1 每天 / 每周看什么（巡检清单）

`healthcheck.sh` 每 5 分钟自动跑（cron 由 `deploy.sh cron` 装），出问题会往飞书发一条。
人只需要按下面这个节奏扫一眼：

### 每天（1 分钟）

```bash
ssh <生产机> 'cd /opt/lqg && docker compose ps'          # 五个容器都 Up + healthy
ssh <生产机> 'tail -50 /opt/lqg/logs/healthcheck.log'    # 有没有告警
ssh <生产机> 'curl -s -o /dev/null -w "%{http_code}\n" https://<域名>/'   # 期望 200
```

### 每周

```bash
# 磁盘（数据盘是第一个会满的东西：备份 dump + 日志 + 渲染中间产物）
ssh <生产机> 'df -h /opt/lqg; du -sh /opt/lqg/* | sort -h'
# 证书剩余天数（healthcheck 在 < 15 天时告警；这里看具体数字）
ssh <生产机> 'openssl x509 -in /opt/lqg/certs/<域名>/fullchain.pem -noout -dates'
# 容器重启次数（后端 OOM 自杀过没有）
ssh <生产机> 'for c in $(docker ps --filter name=lqg-prod- --format "{{.Names}}"); do \
  echo "$c $(docker inspect $c --format "{{.RestartCount}}")"; done'
# 备份是否在（细节与判定归 SYS-BACKUP-001，这里只确认有没有）
ssh <生产机> 'ls -lh /opt/lqg/backup 2>/dev/null | tail -5'
```

### 每月

* 系统与镜像更新：`docker compose pull` 不会动我们自建的镜像，只更新 `postgres/redis/nginx`
  基础镜像 —— **升级前先 `deploy.sh status` 留一张现状，再按 §5 的安全顺序做**。
* 复核 `sys_oss_config` 的 `access_policy` 还是 `0`（私有）：工作台「系统管理 → OSS 配置」
  或 `docker exec -it lqg-prod-postgres psql -U lqg -d lqg -c 'select * from sys_oss_config'`。
* 复核 `admin` 账号仍然是停用 / 随机口令状态（§9 部署手册做的那件事别被谁改回去）。

## §2 阈值一览（改哪个文件改哪一行）

| 指标 | 阈值 | 在哪 | 怎么调 |
|---|---|---|---|
| 容器健康 | `unhealthy` / `Restarting` / 缺失 | `docker-compose.yml` 各服务的 `healthcheck` | 改 `interval` / `retries` / `start_period` |
| 磁盘使用率 | **> 80%** 告警 | `healthcheck.sh` 的 `LQG_HEALTH_DISK_PCT` | 改 `${LQG_DATA_DIR}/healthcheck.env`，或改 `.env` 后重跑 `deploy.sh cron` |
| 证书剩余 | **< 15 天** 告警 | `LQG_HEALTH_CERT_DAYS` | 同上 |
| 证书「续了但没生效」 | 线上指纹 ≠ 磁盘指纹 | `healthcheck.sh` | 不用调，出现就 `docker exec lqg-prod-nginx nginx -s reload` |
| 上传体积 | 60MB | `nginx/workspace.conf` 的 `client_max_body_size` + `proxy-headers.inc` | 两处 + 后端 multipart 上限要同口径 |
| 后端堆 | `-Xmx1g` | `docker-compose.yml` 的 `JAVA_TOOL_OPTIONS` | 按 §3 的容量账调，别只调这一个 |
| PG 内存 | `shared_buffers=1GB` / `max_connections=100` | `docker-compose.yml` 的 postgres `command` | 与后端 `maxPoolSize` 一起看 |
| gotenberg 内存 | 1G | `docker-compose.yml` 的 `mem_limit` | ⚠️ 不要换成 `deploy.resources.limits`（普通 compose 静默忽略） |
| Redis 内存 | 256MB + `allkeys-lru` | `docker-compose.yml` 的 redis `command` | — |

## §3 告警来了怎么办（healthcheck 的四类）

`healthcheck.sh` 告警文本形如 `【lqg 生产告警】<主机> <时间> - <具体项>`。四类各自的第一动作：

### 3.1 容器不健康 / 缺失

```bash
ssh <生产机> 'cd /opt/lqg && docker compose ps'
ssh <生产机> 'cd /opt/lqg && docker compose logs --tail=100 <服务名>'
```

常见原因：

* `backend` 还没起完（`start_period` 180 秒，首次 Flyway 迁移更久）→ 等一次 cron 周期再确认；
* `backend` 起来又死：口令不一致（`LQG_DB_PASSWORD` / `LQG_REDIS_PASSWORD`）、
  `LQG_ENCRYPT_PASSWORD` 没配（`SampleFieldCipher` 会抛 `IllegalStateException`）、
  堆爆（看 §8 部署手册的 OOM 那段）；
* `postgres` unhealthy：`pgdata` 权限（bind mount 必须是 uid 70）、磁盘满（先看 `df -h`）。

### 3.2 磁盘 > 80%

按占用从大到小看：

```bash
ssh <生产机> 'du -sh /opt/lqg/* | sort -h | tail -10'
```

* `backup/` 涨太快 → 30 天生命周期规则没生效（**归 SYS-BACKUP-001**，见它的手册）；
* `logs/` → `docker compose logs` 的轮转在 compose 里配了（`max-size`），后端自己的
  logback 日志要手工清旧的；
* `tmp/` → docx 渲染的中间产物没被清（`spring.servlet.multipart.location` 指向这里）；
* `pgdata/` → 真业务数据在涨，这是**正常的**，只能扩盘（§6）。

### 3.3 证书剩余 < 15 天（或文件缺失）

```bash
ssh <生产机> 'crontab -l | grep acme'                       # 续期任务还在吗
ssh <生产机> 'tail -50 /root/.acme.sh/acme.sh.log'           # 最近一次续期成功了吗
ssh <生产机> 'bash /opt/lqg/remote/03-cert.sh'               # 手工续一次（幂等）
```

* 续期失败最常见的原因是**80 端口的 acme 挑战路径不通**：检查
  `curl -s http://<域名>/.well-known/acme-challenge/test` 是否能被 nginx 处理
  （`nginx/workspace.conf` 里那条 `location ^~ /.well-known/acme-challenge/`）；
* 域名解析被改过 → acme 校验会跑到别处；
* Let's Encrypt 的速率限制（一周同域名 5 次）→ 换 `LQG_CERT_CA=buypass` 或等窗口。

### 3.4 线上证书与磁盘不一致

**几乎一定是「续期没 reload」**（`healthcheck.sh` 专门抓这一条）：

```bash
ssh <生产机> 'docker exec lqg-prod-nginx nginx -t && docker exec lqg-prod-nginx nginx -s reload'
ssh <生产机> 'grep -n Le_ReloadCmd /root/.acme.sh/<域名>_ecc/<域名>.conf'   # 应为 06-cert-install.sh
```

## §4 备份与全量导出（**只留指针**）

备份的实现、生命周期、恢复演练、给甲方的全量导出包，全部归 **SYS-BACKUP-001**。
本手册不重复，只记入口：

| 事项 | 位置 |
|---|---|
| 每日备份脚本 | `code/deploy/prod/backup/backup.sh`（SYS-BACKUP-001） |
| 备份落地 | 生产机 `${LQG_DATA_DIR}/backup/` → OSS 私有桶 `backup/` 前缀（30 天过期） |
| 恢复演练 | `restore-drill.sh`，产出 `doc/ops/restore-drill-YYYYMMDD.md` |
| 全量导出 | `export-all.sh <输出目录>`，产出带 `MANIFEST.txt`（行数 / 文件数 / sha256）的包 |
| OSS 生命周期 | `ossutil lifecycle`（命令写在部署手册 §4.6 的同一层） |

★ 业务文件与备份**前缀分开**（`lqg/` vs `backup/`）：否则生命周期规则会把业务文件一起过期掉。

## §5 变更的安全顺序（改任何东西之前）

1. **先确认备份**：最近一次备份存在且大小 > 0（SYS-BACKUP-001 的 `backup.sh --verify-latest`）。
2. **先留现状**：`bash deploy.sh status > /tmp/lqg-status-$(date +%F).txt`。
3. **配置类**（`.env` / `nginx/*.conf` / `healthcheck.env`）：改 → `upload` → 只 reload / 重启
   受影响的服务（nginx 可以 `nginx -s reload` 不断连接）。
4. **代码类**：见部署手册 §5；**回滚见部署手册 §6**（镜像 tag = 提交号，`deploy.sh rollback <sha>`）。
5. **数据库类**：迁移按「向后兼容」写（加列 / 加表可以，删列 / 改类型不行）——
   回滚应用**不会**回滚 schema（部署手册 §6 的注意）。
6. **改完复核**：`docker compose ps` + `/lqg/sys/ping` + 工作台真登一次。

## §6 扩容与容量

当前规格 2 核 4G / 数据盘（部署手册 §2 的容量账）。三个会先撞到墙的地方：

| 先撞墙 | 症状 | 怎么办 |
|---|---|---|
| 数据盘 | healthcheck 磁盘告警 | 云控制台扩盘 → `growpart` + `resize2fs`（**先看 `df -h` 确认是数据盘还是系统盘**） |
| 内存 | `backend` OOM 自杀、`gotenberg` 被 `mem_limit` 杀 | 升到 4 核 8G，**同时**按比例调 `-Xmx` / `shared_buffers` / `mem_limit`（只调一个会更糟） |
| 单机可用性 | 机器宕 = 全站不可用 | 本票边界**明确不做**多机 / 主从 / 蓝绿（票面 §3）。要做是另一期的事，别在这里顺手加 |

## §7 日志在哪

| 日志 | 位置 | 看什么 |
|---|---|---|
| 后端应用日志 | `${LQG_DATA_DIR}/logs/backend/`（logback 写 `/app/logs`，bind mount 出来） | 业务异常、SQL 慢查询、启动失败栈 |
| nginx access / error | `${LQG_DATA_DIR}/logs/nginx/` | 4xx/5xx、被 nginx 挡掉的请求（413 / 499） |
| 容器 stdout | `docker compose logs <服务>` | 每个容器自己的输出（compose 配了 `max-size` 轮转） |
| healthcheck | `${LQG_DATA_DIR}/logs/healthcheck.log` | 每 5 分钟一条；有告警时是全文 |
| 部署阶段日志 | `${LQG_DATA_DIR}/logs/{up,cert,oss,cron}.log` | 每次 `deploy.sh` 的远端输出 |
| acme.sh | `/root/.acme.sh/acme.sh.log` | 证书签发 / 续期全过程 |

## §8 应急：三个最常见的事故与第一动作

1. **站点打不开**
   `docker compose ps` → 看谁不在 → `docker compose logs --tail=100 <谁>`。
   全在但打不开：`curl -sI http://127.0.0.1/` 在生产机上（绕开 DNS / 证书）判断是 nginx 还是后端。
2. **后端反复重启**
   `docker inspect lqg-prod-backend --format '{{.RestartCount}}'` + `docker compose logs backend | tail -50`。
   口令类问题（PG / Redis / 加密口令）占多数；OOM 看 §3.2 的容量。
3. **证书过期导致小程序全挂**（用户侧症状：小程序报「不在合法域名列表」/ 请求失败）
   先恢复可用性再查根因：
   ```bash
   ssh <生产机> 'bash /opt/lqg/remote/03-cert.sh'   # 重签 + reload
   ```
   然后按 §3.3 查为什么自动续期没成（80 挑战路径 / 解析 / 速率限制）。

## §9 本票没做的运维面（诚实边界）

* **不做**多机 / 主从 / 读写分离 / 蓝绿灰度（票面 §3）。
* **不接**第三方 APM / 日志聚合（票面 §3）—— 本手册 §7 的日志都是「上机器看」。
* **不做**自动回滚（回滚是 `deploy.sh rollback <sha>` 的人工动作）。
* **告警只有一条通道**（飞书 webhook）：webhook 挂了 = 只剩 `/opt/lqg/logs/healthcheck.log`。
  owner 提供 webhook 之前，healthcheck 就是「打日志 + 非零退出」。
