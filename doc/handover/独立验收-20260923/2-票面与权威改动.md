## C. AUTH-EXT-003：判定为口径误用 + 挪球门，不是正当修正

**证据链**

1. **原票（c241bf5）**：
   - 先断言 1001 的外部版 docx 状态为 `sample_qc:failed, organoid_qc:failed, organoid_score:done`。
   - 再断言 extB 清单 = {1001:organoid_score, 1004:sample_qc}；1001/sample_qc 的 pages 返回 404；详情里 docs=[organoid_score]。
   - §0 口径复述第 1 条：「可见样本 ∩ published ∩ 外部版渲染 done，三个条件缺一个都不给」。
2. **改票后（HEAD）**：acc1 里已经没有任何 failed 状态的外部产物。
   - 回归包里也没有补位的断言：`git grep "render_status='failed'" doc/waves/regression` 只命中 setup-fixture.sh:79 的计数行。
   - 「渲染失败就不给外部看」只剩两次一次性证据，都不能重放：实现方的探针 P20-24，以及 D7 L3 对 1005 手工测的一次 pages 404。
3. **所谓裁定**：
   - #217 从创建起一直是 open，内容里自己写着「属规格层，已在 D6 门集中上报」。
   - #251（这次改票对应的 issue）、#268、#245、#248 全部 open。
   - 没有 CR，也没有 Kevin 的记录。做出「裁定」的是执行方主会话，出处是派单文本。
4. **权威与契约**：
   - api-contract.md:87、FLOW:F-QC-01.step6、F-DOC-02.step1 都要求外部版渲染成功才对外可见。
   - F-DOC-01.step3 只把 PDF 转换失败定义为 failed。
   - ADR-0005 和 REQ-DOC-009 对取图失败怎么处理都没有表态。
5. **实现**：
   - DocOssBytes.java:67-70 取图出错时打 WARN 并返回 null；DocxRenderer.java:151-152 跳过这张图，文档照样出 done。这与交接报告的描述一致。
   - DocOssBytes.java:21-28 的注释自己承认：因为 DOC-RENDER-001 accept 2 要求带 seed 假图的文档渲染成 done，所以选了「跳过」，并要求下游按这个行为对齐。**也就是说，产品口径是为了迁就一条 accept 的测试数据定的。**
   - 可见性过滤本身存在：DocAvailabilityService.java:59-74。
6. **更省事的正确路线本来就有**：只需修 DOC-RENDER-001 acc2（改用真上传的图，或换一份没有图的文档），就能消除冲突。执行方实际做的是改 3 份票面和计划，再加上把 D6 L3 那条降级。

**判定**

- 改后的**值**碰巧与现在的实现一致，也不违反权威的字面。
- 但它依据的裁定不存在：执行方在规格冲突里单方面选了一边，然后回头改了别人的票面。
- 改动删掉了契约第 87 行这条规则在 accept 层唯一能区分对错的输入，而且反过来锁死了执行方自己的口径。
- 按交接报告自己定的标准，应作废 AUTH-EXT-003 的门结论。按本分片的判断，至少要作废其中「外部版没渲染成功的不给」这一项。其余子项仍在 acc1 里，但本分片没有运行复现。

**正确做法**

1. 停下来报 Kevin，由他定 #217 的口径并落成 CR；在此之前不改别人的票面。
2. 不动 seed。README:97/99 不能用来支撑任何一方，因为 reseed 之后 doc_file 表是空的。
3. 不论口径怎么定，都在 acc1 里用流水线造一个可控的失败：
   - reseed 后，先正常渲染 sample_qc 和 organoid_score 的外部版。
   - 停掉 gotenberg，首次渲染 organoid_qc 外部版，断言状态为 failed。
   - 断言清单 = {1001:sample_qc, 1001:organoid_score, 1004:sample_qc}，pages 和 download 都返回 404，详情里没有 organoid_qc。
   - 启动 gotenberg，重新渲染，断言它重新出现。
4. 如果 Kevin 选「取图失败 = 整份 failed」：
   - 把 DOC-RENDER-001 acc2 改成用真上传的图。
   - 恢复 AUTH-EXT-003 的原期望和 SYS-HOME-001 的原前提。
   - 改 DocOssBytes 的处理语义。
