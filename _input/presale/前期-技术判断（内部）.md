## 一、这到底是个什么系统

**不只是「送检小程序」，是一个类器官实验室的轻量 LIMS（样本管理系统），小程序只是给外部送样人开的那个口子。**

7 份模板是**同一个样本在不同工序上的 7 张记录**。按我的理解串起来是这样（关系待甲方确认）：

```
外部送检登记（小程序，拍照识别）─┐
                                 ├─→ 收样确认、给内部编号 → 组织处理 → 样本质控（活率判级）
内部直接收样（后台）─────────────┘                                  │
                                         ┌──────────────────────────┼─────────────────────┐
                                         ↓                          ↓                     ↓
                               类器官培养 / 质控              石蜡包埋→脱水→切片→染色     -80 冻存 → 液氮 → 取用
                                         ↓
                               质量评分（自动算）→ 预计筛药 → 反馈送样方
另一个入口：类器官收样（外部直接送类器官来）→ 类器官质控 → …
```

| 模板 | 是什么 | 模板里写明的规则（= 要写的逻辑） |
|---|---|---|
| 样本记录信息表 | 组织样本总台账，14 列 | ① 外部只看**自己样本**的内部编号 + 包埋、培养情况，内部看全部 ② 外部填的实时进台账 ③ 区分内部/外部收样，内部权限高 ④ 加「有无病理（外部）/石蜡切片」 ⑤ 拍照/截图识别，对标顺丰寄件页的「图片识别 / 粘贴并识别」 |
| 类器官收样记录 | 直接收类器官的台账，7 列 | 无 |
| 样本质控表 | 每个样本一份质控报告（Word） | 活率 ≥70% 合格 / 50-70% 基本合格 / <50% 或活细胞 <1×10⁴ 不合格；3 组「图片 + 描述」，图片可放大；活率报告以附件形式挂在表里 |
| 类器官质控表 | 每个类器官一份 | 图片可放大；有「预计筛药」「反馈时间」→ 说明结果要回给送样方 |
| 类器官质量评分表 | 4 项打分，满分 100 | 按区间出分；≤50 偏差 / 50-75 中等 / ≥75 良好 |
| 石蜡包埋送样记录 | 包埋到染色的工序，16 列 | 染色 HE/IF/IHC/其他 用按钮选；marker 表达 阴性/弱/强 用按钮选 |
| -80 冻存 | 冻存库存，9 列 | ① -80 放超两周提示转液氮 ② 液氮取走要追溯，**自动扣支数** |

## 二、技术选型：同意用 dongjiaoshan 那套，但只搬底座不搬业务

**结论：用。** 不只是因为熟——这套栈自带的能力正好压中模板里最硬的几条规则，
下表在 dongjiaoshan 代码里逐个 grep 核过：

| 需求 | RuoYi-Vue-Plus 现成能力 | dongjiaoshan 代码里 |
|---|---|---|
| 外部人员微信登录 | 小程序认证策略 `XcxAuthStrategy` | ✅ 有 |
| 患者姓名、住院号要保护 | `@EncryptField` 字段加密 + `@Sensitive` 列表脱敏 | ✅ 有 |
| 内部看全部、外部看自己的 | `@DataPermission` 行级数据权限 | ✅ 有 |
| 样本照片、活率报告 | OSS 模块，私有桶 + 签名链接 | ✅ 有 |
| 延续现在的 Excel 台账 | EasyExcel 导入导出 | ✅ 有 |
| -80 超两周提醒 | Spring `@Scheduled` | ✅ 有（SnailJob 在 dongjiaoshan 里就是关的，这里也不开） |
| 质控表按原 Word 版式带图导出 | 没有 | ❌ 要新加 poi-tl |

更实际的一条：**/xuqiu → /zhixing 流水线、aliyun-deploy skill、unibest 小程序模板都是照这套栈调出来的**，
换栈等于把这些坑全部重踩一遍。

### 要改的五处（别整套照搬）

1. **只搬底座，不搬业务代码。** 从干净的 RuoYi-Vue-Plus 5.5 + unibest（uni-app + wot-design-uni）起项目，
   复用的是部署清单、OSS 配置、小程序登录与请求层、CI；`ruoyi-djs-*` 业务模块一行不拷
2. **多租户关掉。** 来源单位（医院 / 合作方）不是租户，是一张「来源单位」表 + 外部用户绑定；整个实验室就一个租户
3. **不要 trace-h5，不上 staging/prod 双环境。** 小实验室单环境 + 本地开发够了，一台 2 核 4G 起步
4. **外部隔离不能只靠数据权限注解。** `@DataPermission` 只管「看哪几行」，管不了「只看哪几列」。
   外部接口单独一组（如 `/mp/ext/**`），**只返回专用 VO**，内部实体一个字段不透出——
   把隔离做成一个咽喉，验收时只验这一处，别在每个接口上各自裁字段
5. **拍照识别用国内多模态大模型，不用海外 API。** 送检单上有患者姓名 + 住院号，属于敏感个人信息，不出境。
   走同一个阿里云账号下百炼的通义千问视觉模型：拍照/截图/粘贴文本 → 抽成结构化字段 →
   **回填表单让人确认，不自动提交**。按次计费，这个量级花不了多少，具体型号和单价报价前再核

### 为什么不用低代码（简道云 / 飞书多维表格）

它是最便宜的替代方案，表单 + 台账 + 提醒一两周能搭出来。但会卡在三条：
外部人员要**按行 + 按列**双重隔离、液氮取用要**像库存一样扣数且可追溯**、质控表要**按原 Word 版式带图导出**。
三条都能勉强凑，凑出来比写代码还累，而且患者信息放在第三方 SaaS 上。
**甲方预算极低时可以拿出来当对比的底线方案，不推荐。**

## 三、初步方案

### 3.1 数据模型：一个样本主档挂多条工序记录，不是 7 张平行的表

**最容易做错的一步是照着 7 份模板建 7 张互不相关的表。** 那样「外部填的实时同步到台账」
「外部看到包埋和培养情况」都得靠跨表同步去凑。

应该以**内部编号**为主键建样本主档，工序记录挂在它下面；现在这些 Excel 台账变成**按工序导出的视图**：

| 表 | 对应模板 | 说明 |
|---|---|---|
| 来源单位 / 外部用户 | —— | 外部用户靠邀请码绑定到单位 |
| 样本主档 | 样本记录信息表 + 类器官收样记录 | 样本类型分组织/类器官，来源分内部/外部；**状态字段驱动外部看到的进度** |
| 样本质控 | 样本质控表 | 录入活率自动判级；3 组图片 + 描述；活率报告作附件 |
| 类器官质控 | 类器官质控表 | |
| 类器官评分 | 类器官质量评分表 | 4 项输入自动出分，区间做成可配字典 |
| 包埋染色 | 石蜡包埋送样记录 | 一个蜡块测多个 marker 的话，marker 表达做子表（待确认） |
| 冻存批次 + 出入库流水 | -80 冻存 | **余量 = 流水累计**，不让人直接改数字，追溯天然就有 |

顺带：样本记录表里「质控表 有/无」「细胞活率报告 有/无」这两个按钮，在系统里应该**自动得出**
（挂没挂质控记录、传没传报告），不让人手点——手点的迟早和实际对不上。

### 3.2 三个端

| 端 | 谁用 | 做什么 |
|---|---|---|
| 小程序·外部 | 合作单位的送检人（不是患者，具体是谁 Kevin 去确认） | 邀请码绑定单位 → 送检登记（拍照识别回填）→ 我的样本（内部编号 + 进度） |
| 小程序·内部 | 实验员 | 只放**人在冰箱前、手上戴手套**的动作：收样拍照、冻存取用登记 |
| 管理后台 | 实验员 / 负责人 | 全部台账、质控表编辑与导出、评分、包埋染色、冻存库存与到期提醒、单位与用户管理 |

### 3.3 一期范围：7 份模板就是范围闸

**一期 = 这 7 份模板上写明的字段和规则，一条不多。** 模板之外冒出来的一律进二期或走变更。

一期：
- 外部送检登记 + 拍照识别 + 进度查看（行列双重隔离）
- 内部/外部收样、内部编号生成、样本台账（含「有无病理/石蜡切片」）
- 样本质控：活率自动判级、图片放大、按原版式导出 Word
- 类器官收样、质控、评分自动计算
- 石蜡包埋染色记录（染色、marker 表达按钮选择）
- 冻存：-80 超两周提醒、转液氮登记位置、取用扣支数并留痕

二期 / 扩展（先不报）：
- 样本管条码标签打印 + 扫码定位
- 统计看板（送样量、质控合格率、类器官成功率）
- 药敏实验结果与报告
- 对接医院系统

## 四、风险（出方案前要想清楚的）

1. **小程序类目风险不大，但留条退路。** 登记送检的是合作单位的人，不是患者，本质是 B 端办公工具，
   按工具/办公类提审即可；相机、相册要在隐私保护指引里声明。万一审核因为表单里有供体信息要资质，
   外部送检改走 H5 网页 + 手机号登录，uni-app 同一套代码编译出来
2. **供体信息照样要保护。** 登记人不是患者，但模板里有供体姓名、住院号，仍属敏感个人信息。
   默认加密存储、列表打码、外部接口不返回，不单独去问甲方
3. **提醒通道。** 普通类目的小程序订阅消息只能一次性订阅（用户授权一次发一条），撑不起「到期天天提醒」。
   -80 到期提醒建议走后台首页待办 + 企业微信/钉钉群机器人（看实验室用哪个），短信兜底
4. **识别准确率不能承诺。** 手写单、模糊截图识别不准是常态。对外口径统一为「帮着填，人确认」
5. **显微镜图片格式。** 显微镜相机常导出 TIFF 大图，浏览器和小程序都预览不了，上传时要转预览图、原图另存。
   开发期要一张真实样图确认

## 五、要问甲方的（只留三条：定架构的、卡上线的）

| # | 问题 | 不问清会怎样 |
|---|---|---|
| 1 | **外部用户是谁、能看到什么**：登记送检的是哪类人（不是患者，Kevin 去确认）？同单位的人能不能互看对方送的样？能看的只有进度，还是也看质控结论、评分、筛药反馈？ | 决定隔离按人还是按单位、外部接口返回哪些字段。错了改的是权限模型，不是页面 |
| 2 | **编号怎么贯穿**：一个样本从收样到质控、类器官、包埋、冻存，是不是一个内部编号走到底？石蜡块编号、冻存批次和它什么关系？直接收的类器官和组织培养出来的类器官是不是两条线？ | 整个数据模型的主干，定了就不能改 |
| 3 | **小程序和云账号挂谁名下**：用哪个主体注册，有没有认证过的微信公众平台账号？ | 小程序备案、域名备案都要主体出面，各要一到几周，不启动就卡上线 |

### 其余的开发期再定，不发甲方

不影响架构，拆需求时先按默认值做，攒到一起找甲方过一遍：

| 事项 | 默认先按 |
|---|---|
| 拍照识别拍的是什么单据 | 大模型通用抽取 + 人工确认；开发时要 3-5 张脱敏样张调提示词 |
| 质控表 Word 还原到什么程度 | 按模板版式导出带图 Word；活率报告列成附件链接，不做双击打开的嵌入 |
| 评分边界（50、75 落哪档，「40~80」含不含端点，「培养前样本评分」从哪来） | 区间做成可配字典，口径定了改配置不改代码 |

| 历史 Excel 要不要导入、月样本量 | 一期不含导入；服务器 2 核 4G 起 |
| 供体姓名、住院号怎么存 | 加密存储 + 列表打码，外部接口不返回 |
